Requirements

18 functional and 12 non-functional requirements from four workshops.

Functional Requirements — NexusCRM Platform

Gathered via 4 requirements workshops with Sales, Customer Success, and Engineering (Weeks 1–2), and prioritized with the Product Owner role (held by the PM for this project).

Authentication & Permissions

ID Requirement Priority
FR-01 Users authenticate via company SSO (existing Google Workspace) Must
FR-02 Three role tiers: Admin, Sales Rep, Read-only (Customer Success) Must
FR-03 Admins can deactivate a user without deleting their historical activity log Must

Contact & Account Management

ID Requirement Priority
FR-04 Create, edit, and merge contact records, with a duplicate-detection warning on save Must
FR-05 Contacts can be grouped under a parent Account (company) record Must
FR-06 Full activity history (calls, emails, notes) visible on a contact's timeline Must
FR-07 Bulk import of contacts via CSV with field mapping Should

Deal Pipeline

ID Requirement Priority
FR-08 Kanban-style pipeline view with configurable deal stages Must
FR-09 Drag-and-drop stage changes must NOT require a page reload — flagged by Sales power-users as a dealbreaker for daily adoption during requirements workshops Must
FR-10 Deal value roll-up visible per stage and per sales rep Must
FR-11 Won/lost reason capture on deal close Should

Reporting (Release 2)

ID Requirement Priority
FR-12 Live pipeline dashboard replacing the manual monthly report Must
FR-13 Exportable reports (CSV, PDF) for leadership review Should
FR-14 Rep-level and team-level performance views Should

Integrations (Release 2)

ID Requirement Priority
FR-15 Two-way email sync (send/receive logged against contact timeline) Must
FR-16 Zapier integration for at least 3 common triggers (new deal, stage change, deal won) Should

Data Migration

ID Requirement Priority
FR-17 Guided migration tool from legacy database with duplicate resolution step Must
FR-18 Migration dry-run mode with a report before committing changes Must

See Non-Functional Requirements for performance, security, and compliance requirements.

Non-Functional Requirements — NexusCRM Platform

Performance

ID Requirement
NFR-01 Pipeline board loads in under 2 seconds for up to 2,000 active deals
NFR-02 Dashboard queries (Release 2) return in under 3 seconds at current data volume

Security & Compliance

ID Requirement
NFR-03 All customer data hosted on Meridian's existing EU infrastructure (data residency)
NFR-04 Role-based access control enforced at the API layer, not just the UI
NFR-05 Full audit log of record access and changes, retained per Meridian's data retention policy
NFR-06 Right-to-erasure requests supported via an admin-initiated data purge workflow
NFR-07 External security/GDPR audit must pass with no critical findings before Release 2 go-live

Reliability

ID Requirement
NFR-08 99.5% uptime target during business hours (internal tool, not customer-facing)
NFR-09 Daily automated backups with a tested restore procedure

Usability

ID Requirement
NFR-10 Core workflows (add contact, move deal stage, log activity) achievable in ≤ 3 clicks
NFR-11 Responsive web layout supporting desktop and tablet (mobile native explicitly out of scope)

Maintainability

ID Requirement
NFR-12 API documented and versioned to support the Release 2 Zapier integration and any future integrations
